## The through-line

What began as "the admin-portal tenant picker writes to the wrong tenant" turned
up **ten live production defects**. The pattern worth remembering: almost all of
them were *silent* — the system answered 200 while writing to the wrong tenant,
or while doing nothing at all. Assume a green response proves less than it looks
like it proves.

1. Misdirected admin writes — no selector from the portal, unaudited super-admin
   fallback in the backend. See [[feedback_admin_tenant_selector]].
2. `/tenants` 403 — ingress `path: /t` matched it, because Traefik reads
   `pathType: Prefix` as a **string** prefix. Now `/t/`.
3. 403 instead of 401 for a signed-out admin hitting the selector.
4. One refresh cookie shared across tenants (B-TEN-7) → `wf_refresh_<slug>`,
   legacy `refresh_token` still written for the Safe Space proxy.
5. No Bean Validation provider (B-API-2) — `@Valid` enforced nowhere, malformed
   input produced 500s.
6. Order funnel + payment webhooks 403'd in production by
   `AppAuthorizationFilter`.
7. A tenant's OIDC secret shown in a `window.alert`.
8. Password hints overlapping the fields below them.
9. Passkey sign-in impossible — ceremony keyed by the MFA challenge JWT
   (overflowed `varchar(128)`), tenant-unaware username lookup, and no passkey
   UI on the login page. Three causes, one symptom.
10. Outbound email never configured after the GCP move — see
    [[sendgrid_trial_deadline]].

Plus the meta-defect: `disableNameSuffixHash: true` meant **config changes
deployed without restarting any pod**, so #10 looked fixed and wasn't.

## `/login` — answered, do not re-litigate

`/login` serves the **admin portal SPA**, not `LoginController`, and that is
correct. The Ingress forwards `/api`, `/t/`, `/saml2`, `/scim` and `/health` to
the backend and everything else to the portal. The OIDC `/authorize` state
machine redirects unauthenticated users to
`{tenant-origin}/login/?oidcReturnTo=…` *expecting the SPA*, which reads that
parameter (`core/oidc-continuation.ts`) and applies tenant branding via
`TenantBrandingService`. `LoginController` serves the same paths for
deployments that reach the API directly with no portal in front — a
docker-compose self-host. Both exist on purpose.
